Database Design

Blood Bank Data Model

Entity–relationship diagram for the Django blood-donor management system. Ten entities span three Django apps — core (institutions & staff), donors (donor registry, campaigns, donations, collected units) and inventory (requests, issuance, stock thresholds) — plus Django's built-in auth.User, which several models reference for accountability (who recorded, handled or issued a record).

Relationships & cardinality

Every relationship below is implemented as a Django ForeignKey or OneToOneField (see field names in the diagram), except the last row, which is a shared lookup key rather than a database relationship.

RelationshipCardinalityMeaning
User → InstitutionMembership1 : 1 A staff account is linked to at most one institution membership record (OneToOneField).
Institution → InstitutionMembership1 : * One institution has many staff members attached via their memberships.
Institution → DonationCampaign1 : * An institution organises many donation campaigns over time.
Donor → Donation1 : * A donor can make many donations (subject to the 56-day eligibility rule enforced in code).
DonationCampaign → Donation1 : * (optional) A campaign can group many donations; a donation may also be unlinked to any campaign (null=True).
User → Donation1 : * (optional) The staff member who recorded a donation; nullable so historical records survive a user's removal.
Donation → BloodUnit1 : 1 A collected donation produces exactly one trackable blood unit (OneToOneField); a deferred donation produces none.
Institution → BloodRequest (requestor)1 : * The institution that sends a blood request (usually a hospital).
Institution → BloodRequest (receiver)1 : * The institution asked to fulfil the request (usually the blood bank) — a second, independent foreign key to the same model.
User → BloodRequest1 : * (optional) The staff member who handled/triaged the request.
BloodRequest → IssuedUnit1 : * A request can be fulfilled by issuing several individual units against it.
BloodUnit → IssuedUnit1 : 1 Once a specific unit is issued it is linked to exactly one issuance record (OneToOneField) and cannot be issued twice.
User → IssuedUnit1 : * (optional) The staff member who physically released the unit.
StockThreshold ⇢ BloodUnitlogical Not a foreign key — each threshold row is compared at query time against available BloodUnit rows sharing the same blood_group to drive the dashboard's low-stock alerts.
